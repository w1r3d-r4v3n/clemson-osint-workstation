# Security policy

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature when it is enabled for this repository. Do not open a public issue for an unpatched vulnerability.

Never include credentials, tokens, private case material, student data, research-subject data, or an unredacted machine path in a report. Use a synthetic proof of concept and state the affected commit and platform.

If private reporting is unavailable, contact the repository owner through a private Clemson-approved channel and provide only enough information to arrange secure follow-up.

## Supported version

Only the latest tagged release receives security fixes. Ubuntu, VirtualBox, Python applications, and linked public services have independent support and disclosure policies.

## Scope

Security issues in the repository's scripts and local portal are in scope. Vulnerabilities in third-party tools should first be reported to the relevant upstream project unless this repository introduces the vulnerable configuration.
